# 模拟餐厅点餐系统 · 数据库设计说明

> 数据库：SQLite（`restaurant-server/data/restaurant.db`）
> 建表脚本：`src/db/schema.sql`　初始数据：`src/db/seed.sql`

## 一、设计目标

1. **结构清晰**：按「分类 → 菜品 → 订单 → 订单明细」的主线组织，符合点餐业务的自然流程。
2. **数据一致**：下单时通过数据库事务保证订单主表、订单明细、菜品销量库存三者同步。
3. **可追溯**：订单明细保存下单时的菜品名称与单价快照，菜品后续改价不影响历史订单金额。
4. **可扩展**：预留 `status`、`stock` 等字段，便于后续扩展后台管理、库存预警等功能。

## 二、实体关系（E-R）

```
┌──────────────┐          ┌──────────────┐
│   category   │ 1      n │     dish     │
│   菜品分类    │──────────│    菜品       │
└──────────────┘          └──────┬───────┘
                                 │ 1
                                 │
                                 │ n
┌──────────────┐          ┌──────┴───────┐          ┌──────────────┐
│ dining_table │ 1      n │    orders    │ 1      n │  order_item  │
│    餐桌       │──────────│    订单       │──────────│   订单明细    │
└──────────────┘  桌号关联 └──────────────┘          └──────────────┘
```

- 一个**分类**包含多个**菜品**（1:n，外键 `dish.category_id`）
- 一张**餐桌**可以产生多个**订单**（1:n，通过 `table_no` 关联）
- 一个**订单**包含多条**订单明细**（1:n，外键 `order_item.order_id`，级联删除）
- **菜品**与**订单明细**通过 `dish_id` 关联，明细同时冗余保存菜品名称与单价

## 三、数据表清单

| 序号 | 表名 | 中文名 | 说明 |
| ---- | ---- | ------ | ---- |
| 1 | `category` | 菜品分类表 | 热菜、凉菜、主食、饮品 |
| 2 | `dish` | 菜品表 | 菜单数据，含价格、销量、库存 |
| 3 | `dining_table` | 餐桌表 | 桌号、座位数、使用状态 |
| 4 | `orders` | 订单主表 | 一笔订单一条记录 |
| 5 | `order_item` | 订单明细表 | 订单内每道菜的明细 |

## 五、索引设计

| 索引名 | 所在表 | 字段 | 用途 |
| ------ | ------ | ---- | ---- |
| idx_dish_category | dish | category_id | 按分类查询菜品（点餐页高频操作） |
| idx_dish_status | dish | status | 过滤停售菜品 |
| idx_orders_created | orders | created_at | 按时间倒序查询订单、按日统计 |
| idx_orders_status | orders | status | 按状态筛选订单（后厨看板） |
| idx_item_order | order_item | order_id | 查询某订单的全部明细 |

## 六、关键业务规则与一致性设计

1. **下单事务**：`POST /api/orders` 使用 `BEGIN / COMMIT / ROLLBACK` 包裹四步操作
   ① 写入 `orders` ② 写入 `order_item` ③ 扣减 `dish.stock` 并累加 `dish.sales` ④ 更新餐桌状态。
   任一步失败整体回滚，避免出现"订单存在但明细缺失"的脏数据。
2. **价格以服务端为准**：下单金额全部由数据库中的 `dish.price` 计算，不信任客户端传入的价格，防止篡改。
3. **名称价格快照**：`order_item` 冗余存储 `dish_name`、`price`，菜品后续改名改价不影响历史订单。
4. **库存校验**：下单前校验 `stock >= count`，库存不足直接返回业务错误并回滚。
5. **订单状态机**：仅允许 `待处理 → 制作中 → 已完成` 及任意状态 → `已取消`；取消订单时自动回补库存、回退销量，完成订单时把餐桌置为空闲。
6. **外键约束**：`PRAGMA foreign_keys = ON`，删除订单时明细级联删除，不会留下孤儿记录。

## 七、接口清单

| 方法 | 路径 | 说明 |
| ---- | ---- | ---- |
| GET | `/api/health` | 健康检查 |
| GET | `/api/categories` | 分类列表（含各分类菜品数量） |
| GET | `/api/dishes?categoryId=&keyword=` | 菜品列表，支持分类过滤与名称搜索 |
| GET | `/api/dishes/:id` | 菜品详情 |
| GET | `/api/tables` | 餐桌列表及占用状态 |
| POST | `/api/orders` | 提交订单（事务） |
| GET | `/api/orders?status=&limit=` | 订单列表（含明细） |
| GET | `/api/orders/:orderNo` | 订单详情 |
| PUT | `/api/orders/:orderNo/status` | 更新订单状态 |
| GET | `/api/stats/summary` | 经营概况：订单数、营业额、客单价、餐桌占用 |
| GET | `/api/stats/top?limit=5` | 菜品销量排行 |
| GET | `/api/stats/category` | 分类营业额占比 |

统一响应格式：

```json
{ "code": 0, "message": "ok", "data": { } }
```

`code = 0` 表示成功，非 0 表示业务失败（如库存不足、桌号不存在）。

## 八、典型查询 SQL（报表用）

```sql
-- 1. 今日营业额与订单数
SELECT COUNT(*) AS orderCount, SUM(total_amount) AS turnover
  FROM orders
 WHERE status != '已取消'
   AND date(created_at) = date('now', 'localtime');

-- 2. 菜品销量排行 TOP5
SELECT i.dish_name, SUM(i.count) AS sold, SUM(i.subtotal) AS amount
  FROM order_item i
  JOIN orders o ON o.id = i.order_id
 WHERE o.status != '已取消'
 GROUP BY i.dish_id, i.dish_name
 ORDER BY sold DESC
 LIMIT 5;

-- 3. 分类营业额占比
SELECT c.name AS category, IFNULL(SUM(i.subtotal), 0) AS amount
  FROM category c
  LEFT JOIN dish d       ON d.category_id = c.id
  LEFT JOIN order_item i ON i.dish_id = d.id
  LEFT JOIN orders o     ON o.id = i.order_id AND o.status != '已取消'
 GROUP BY c.id
 ORDER BY amount DESC;

-- 4. 客单价 = 营业额 / 订单数
SELECT ROUND(SUM(total_amount) / COUNT(*), 2) AS avgAmount
  FROM orders WHERE status != '已取消';

-- 5. 桌位使用率
SELECT SUM(CASE WHEN status = 1 THEN 1 ELSE 0 END) || ' / ' || COUNT(*) AS usage
  FROM dining_table;
```

## 九、迁移到 MySQL 的说明

本项目使用 SQLite 便于零配置演示，语法与 MySQL 基本一致，迁移时只需：

| SQLite 写法 | MySQL 写法 |
| ----------- | ---------- |
| `INTEGER PRIMARY KEY AUTOINCREMENT` | `INT UNSIGNED AUTO_INCREMENT PRIMARY KEY` |
| `TEXT`（时间） | `DATETIME` |
| `datetime('now','localtime')` | `NOW()` |
| `IFNULL()` | `IFNULL()`（MySQL 同样支持） |
| `REAL` | `DECIMAL(10,2)`（金额建议用定点数） |
