## 二、主流程演示

### 第 1 步：顾客点餐

**操作**

1. 进入点餐页
2. 选 2–3 道菜，加入购物车
3. 进入确认页，选桌号（如 A01），填备注
4. 提交订单

**讲解词**

> 顾客端只负责选菜和提交，价格不由前端决定。
> 后端会重新查菜品价格、校验库存，再写订单主表和明细。

**展示点**

- 订单提交成功，生成订单号
- 订单页能看到明细和总金额
- 数据库 `orders` 和 `order_item` 各多了一条记录
- 对应菜品 `stock` 减少、`sales` 增加

### 第 2 步：老板登录

**操作**

1. 点餐页右上角「老板入口」
2. 输入演示密码 `8888`
3. 进入订单看板

**讲解词**

> 老板端不是靠前端隐藏入口来保护，而是后端统一鉴权。
> 登录成功返回 token，后续请求放在 `X-Owner-Token` 请求头里。

**展示点**

- 登录成功跳转订单看板
- 不带 token 请求 `/api/owner/orders` 返回 401

### 第 3 步：接单 → 出餐

**操作**

1. 在待处理订单点「接单」
2. 状态变成「制作中」
3. 再点「出餐」
4. 状态变成「已完成」

**讲解词**

> 订单状态不是随便改的，`OrderService` 里有状态机：
> 待处理 → 制作中 → 已完成，已完成的订单不能再回退。

**展示点**

- 状态按顺序变化
- 已完成订单不再显示操作按钮
- 餐桌状态随后刷新

### 第 4 步：经营统计

**操作**

1. 点「经营统计」
2. 查看今日订单、营业额、待处理订单、热销榜、分类占比

**讲解词**

> 统计不是前端算的，而是后端聚合 SQL 查出来的。
> 营业额、客单价、热销榜都来自数据库。

### 第 5 步：取消订单 + 库存回滚

**操作**

1. 再下一单
2. 在老板端点「取消」
3. 回到顾客端/数据库看库存

**讲解词**

> 取消订单不是只改一个状态。
> 后端在同一事务里按订单明细逐条回加库存、回减销量，再重算餐桌状态。

**展示点**

- 订单状态变为「已取消」
- 菜品库存恢复到下单前
- 销量也回退

## 三、异常边界演示

### 1. 未登录访问老板接口

```powershell
curl.exe -i http://localhost:8080/api/owner/orders
```

预期：

```text
HTTP/1.1 401
{"code":401,"message":"未登录或登录已过期","data":null}
```

讲解：老板接口由拦截器统一保护。

### 2. 非法状态流转

先拿一个「已完成」订单，再尝试改回「制作中」：

```text
PUT /api/owner/orders/{orderNo}/status
{"status":"制作中"}
```

预期：返回业务错误，提示不能从「已完成」变为「制作中」。

讲解：状态机集中管理，避免业务数据被改乱。

### 3. 库存不足

把某道菜库存改成 0，再下单。

预期：返回“库存不足”，订单不生成、库存不变。

讲解：下单前校验 + 事务回滚，保证不会出现半成品订单。

## 六、常见问题

### 后端启动失败

先看 8080 是否被占用：

```powershell
Get-NetTCPConnection -LocalPort 8080 -State Listen
```

### 小程序请求失败

- 确认后端已启动
- 开发者工具「详情 → 本地设置 → 不校验合法域名」已勾选
- `utils/api.js` 的 `BASE_URL` 是 `http://localhost:8080/api`

### 数据库连不上

- 确认 MySQL 监听 3307
- 确认 `application.yml` 的端口、库名、账号密码正确
- 先用 `mysql -h127.0.0.1 -P3307 -uroot -p123456` 手动连一次

### 演示数据乱了

重新执行 `schema.sql` + `seed.sql`，再走主流程。
